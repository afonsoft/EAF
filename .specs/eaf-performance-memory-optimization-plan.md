# EAF — Performance and Memory Optimization Plan

## Summary

Establish measurable performance targets and a concrete roadmap to reduce memory usage, improve API latency and shrink Angular bundle size in the EAF middleware and templates.

## Current Observations

- Angular template uses minified CSS/JS bundles but still contains jQuery, `ngx-bootstrap`, legacy Metronic assets and a large `service-proxies.ts`.
- Backend has no explicit caching module for distributed Redis.
- No `IAsyncEnumerable` or streaming patterns observed in application services.
- Chat SignalR `ChatHub` uses `memoryCache` but no backplane for multi-instance deployments.
- ABP `UnitOfWork` defaults can hold DbContexts open for long durations.

## Targets

| Metric | Target | Measurement |
|---|---|---|
| Angular initial bundle | < 1 MB (gzipped main) | `ng build --stats-json` |
| First Contentful Paint (FCP) | < 1.5 s | Lighthouse |
| API p99 response | < 200 ms for reads | App metrics / OTel |
| Backend memory per request | flat | `dotnet-counters` / `dotnet-gcdump` |
| Test coverage | ≥ 90 % | coverlet / SonarCloud |

## Backend Actions

### 1. Repository and Query Optimization
- Avoid `ToList()` before filtering; project with `Select`.
- Use `AsNoTracking()` for read-only queries.
- Add composite indexes for common filters (`TenantId`, `IsDeleted`, `CreationTime`).
- Use `IAsyncEnumerable<T>` for large exports.

### 2. Caching
- Introduce `Eaf.RedisCache` module for `ICacheManager` distributed cache.
- Cache user permissions and tenant settings.
- Add cache invalidation on entity changes via domain events.

### 3. Background Jobs
- Move heavy work to Hangfire (email, report generation, payment reconciliation).
- Use `BackgroundJob.Enqueue` / `RecurringJob`.

### 4. Memory Leak Prevention
- Ensure `UnitOfWork` is short-lived.
- Avoid capturing `IServiceProvider` in static/singleton lambdas.
- Review `ChatHub` lifetime and `IOnlineClientManager` memory usage.

### 5. Async Patterns
- Add `Async` suffix to all async public methods.
- Never use `.Result` or `.Wait()`.
- Use `ConfigureAwait(false)` in library code.

## Frontend Actions

### 1. Bundle Size
- Remove jQuery and legacy `eaf-web-resources` if not needed.
- Tree-shake `lodash` by importing per-method (`lodash-es`).
- Split admin pages with Angular lazy loading.
- Enable build budgets in `angular.json`.

### 2. PrimeNG On-Demand
- Import components individually instead of full `primeng` modules.
- Use PrimeNG unstyled mode to avoid unused theme CSS.

### 3. Service Proxies
- `service-proxies.ts` is generated by NSwag; do not edit manually.
- Investigate splitting by feature module instead of one giant file.

### 4. Runtime Performance
- Use `OnPush` change detection where possible.
- Debounce search inputs and table filters.
- Use virtual scroll for large tables.
- Cache HTTP GETs with `HttpClient` interceptors or `@angular/service-worker`.

### 5. Memory
- Unsubscribe from RxJS subscriptions (`takeUntil`, `async` pipe).
- Avoid storing large DTOs in memory; use pagination.

## Implementation Status (2026-08)

Partial. Some async/await patterns exist, but no comprehensive performance instrumentation, no Redis cache module, and no lazy-loaded admin modules. Angular bundle budgets are not enforced.

## Migration Plan
1. Add performance instrumentation (OpenTelemetry + `dotnet-counters`).
2. Create `Eaf.RedisCache` module.
3. Audit top 10 API endpoints for N+1 and missing indexes.
4. Add Angular `budgets` to `angular.json`.
5. Lazy-load admin modules.
6. Remove/replace jQuery and `ngx-bootstrap` incrementally.
7. Run Lighthouse CI on PRs.

## Impact
- **Medium**: requires new module and infrastructure.
- **High**: improves scalability and user experience.
- **Medium**: reduces hosting costs.

## Risks
- Caching adds complexity and invalidation bugs.
- Lazy loading can break deep linking if route guards are not adjusted.
- NSwag split requires template changes.
